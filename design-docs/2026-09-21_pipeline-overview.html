Yomiagen パイプライン全体構造

文書の取り込みから読み上げ用音声の完成までを、6 つのステージと編集可能な中間ファイルでつなぐ仕組みを説明する。

Yomiagen は、HTML・Markdown・テキストを「耳で理解しやすい台本」に変換し、VOICEVOX で音声化するコマンドラインツールである。処理を一枚岩にせず 6 ステージに分け、各結果をジョブディレクトリへ保存することで、自動実行と人手によるレビューを同じ仕組みで両立している。

どのステージが何を受け取り、何を作るのか。読みやアクセントをどこで直すのか。変更後にどこから再実行すればよいのか。外部サービスの失敗時に何が起きるのかを、実装コードを読まずに把握できる。

まず押さえる3つの考え方

6独立した処理ステージ

取り込み・台本化・発話化・クエリ生成・合成・組み立てに分離する。

File中間状態の保存単位

専用UIではなく、読み書きできる JSON と WAV をレビュー面として使う。

Hash再実行の判定方法

入力内容のハッシュで変更を検出し、変更のない処理と音声合成を省略する。

1. ステージを順番につなぐ

パイプラインは ingest → script → pronounce → query → synthesize → assemble の順で進む。run コマンドは全ステージを連続実行し、個別コマンドは指定したステージだけを実行する。

2. 中間生成物を人が直せる

各ステージは次のステージへメモリ上の値を直接渡さず、ジョブディレクトリ内のファイルへ書き出す。利用者は 30_speech.json で発話単位や調整命令を直すことも、35_query/*.json で VOICEVOX の AudioQuery を直接直すこともできる。

3. 変更された部分だけをやり直す

ステージ入力と設定からハッシュを計算し、前回と同じなら処理を省略する。音声合成はチャンクごとにクエリ内容を記録するため、AudioQuery を 1 ファイルだけ編集すると、そのチャンクだけを再合成できる。

全体フロー

flowchart LR Input["入力<br/>URL / HTML / Markdown / Text"] --> Ingest["1. ingest<br/>文書構造を抽出"] Ingest --> D["10_document.json"] D --> Script["2. script<br/>耳で聞ける台本へ変換"] OpenAI["OpenAI<br/>任意"] -.-> Script Script --> S["20_script.json"] S --> Pronounce["3. pronounce<br/>発話分割・間・読み"] Pronounce --> SP["30_speech.json"] SP --> Query["4. query<br/>AudioQuery・抑揚調整"] Voicevox["VOICEVOX ENGINE"] <--> Query Query --> Q["35_query/*.json"] Q --> Synth["5. synthesize<br/>チャンク音声を生成"] Voicevox <--> Synth Synth --> W["40_chunks/*.wav"] W --> Assemble["6. assemble<br/>結合・章・圧縮"] FFmpeg["ffmpeg"] -.-> Assemble Assemble --> Output["50_output.wav / .m4a"]

実線はデータの流れ、点線は外部機能の利用を表す。OpenAI は台本品質を上げるための任意依存であり、APIキーがない場合は原文構造を保つローカル変換で処理を継続する。VOICEVOX は現在の音声合成に必要な依存である。

各ステージの役割

1. ingest — 入力を論理文書にする

URLならHTTPで取得し、ローカルファイルならそのまま読む。HTMLでは article、main、body の優先順で本文領域を探し、見出し・段落・リスト・引用・コード・表・キャプションへ分ける。ナビゲーション、サイドバー、スクリプトなどは除外する。

重要な設計判断
「きれいなプレーンテキスト」へ潰さず、見出しレベルやコードなど、後段の読み替えに必要な構造を残す。
キャッシュ入力
取得した原文の内容と入力種別。
実装
internal/ingest

2. script — 目で読む文書を耳で聞く台本にする

OpenAI Responses APIが利用できる場合は、表・コード・視覚参照を音声向けの文章へ変換する。これは要約ではなく媒体変換であり、元の情報をできるだけ保つ。数字や記号を含む技術用語はVOICEVOXが誤読しやすいため、読みやすい形へ展開し、繰り返し使う特殊な読みは辞書候補として出力する。

処理を停止せず、Documentの各ブロックをそのままUtteranceへ移す。音声向けの言い換え品質は下がるが、ローカル環境だけで最後まで実行できる。

大きな文書
ブロック境界を保ったまま、およそ 4,000 文字ごとに分割して送る。
文脈の連続性
次のリクエストへ直前出力の末尾 200 文字を渡す。
実装
internal/script

3. pronounce — 台本を合成単位へ分ける

台本の発話を文境界で分割し、既定では最大 200 文字のチャンクへ詰める。長すぎる文は読点、それでも長ければ文字数で切る。見出しには遅めの話速と前後の間、通常段落には段落末の間、疑問文には疑問上昇調を付ける。

ここで付ける調整は音声データではなく、global や interrogative といった操作データである。利用者は 30_speech.json の ops を編集して調整を追加できる。

4. query — エンジン固有の表現力を適用する

各チャンクをVOICEVOXへ送り、ネイティブなAudioQueryを生成する。処理前に /engine_manifest を読み、エンジンが申告した機能だけを使う。未対応操作は既定では警告して省略し、厳格モードではエラーにできる。

表 2: VOICEVOX向けに実装済みの調整操作
操作効果主な用途
accentアクセント核を変更し、モーラ情報を再計算固有名詞のアクセント修正
emphasize対象モーラのピッチを加算語の強調
lengthen母音・子音の長さを倍率変更タメやゆっくりした発音
devoice母音を無声化自然な日本語発音
pauseアクセント句末の無音時間を設定理解しやすい間
interrogative疑問上昇調を有効化疑問文
global話速・音高・抑揚・音量・前後無音を設定文書全体や見出しの調子
patchネイティブJSONへ直接マージ名前付き操作にない実験的調整

アクセントのようにエンジン再計算が必要な操作を先に適用し、/mora_data を 1 回だけ呼ぶ。その後にピッチ・音長・無声化・パッチを適用する。これにより、直接調整した値が再計算で消えることを防ぐ。

5. synthesize — チャンクごとに音声化する

35_query の各ファイルをVOICEVOXへ送り、対応するWAVを 40_chunks に保存する。既定の並列度は 1 である。VOICEVOX ENGINEは内部で合成を直列化するため、同時リクエストを増やしても実測上の短縮効果がなかったためである。

  • クエリ内容のハッシュが同じでWAVが存在する場合は合成を省略する。
  • --only c0003,c0007 で対象チャンクを限定できる。
  • 失敗時は最大 3 回、待ち時間を増やしながら再試行する。
  • すべて失敗したチャンクは 1 秒の無音に置き換え、ジョブ全体は継続する。
  • 文字数、音声秒数、処理時間、料金を cost.jsonl へ追記する。

6. assemble — 1本の音声ファイルへまとめる

チャンク順にWAVの fmt と data を読み、形式が同じことを確認してサンプル単位で連結する。同時に、見出しチャンクの開始位置からチャプター時刻を計算する。

常に 50_output.wav を作り、ffmpegが利用できればラウドネス正規化とチャプター埋め込みを行ってM4AまたはMP3へ変換する。ffmpegが使えない場合は警告を出し、WAVを最終成果物として残す。

ジョブディレクトリ

1回の変換処理を「ジョブ」と呼ぶ。既定の保存場所は ~/.local/share/yomiagen/jobs/<job-id> で、YOMIAGEN_HOME により変更できる。

レビューと部分再実行

最初から最後まで自動実行する

yomiagen run article.html

違和感のあるチャンクだけ調整する

  1. 30_speech.json で元の発話とチャンクIDを確認する。
  2. 35_query/c0042.json のアクセントやピッチを編集する。
  3. c0042 だけを再合成して試聴する。
  4. 問題がなければ全チャンクを再結合する。
yomiagen show JOB_ID speech
$EDITOR "$(yomiagen path JOB_ID query)/c0042.json"
yomiagen synthesize JOB_ID --only c0042
yomiagen assemble JOB_ID

特定ステージから再開する

# 台本を手編集した後、発話分割から最後まで実行する
yomiagen run JOB_ID --from pronounce

# キャッシュを無視してクエリ生成からやり直す
yomiagen run JOB_ID --from query --force

--force は対象ステージの既存出力を上書きする。手編集した 35_query/*.json を残したい場合は、query --force を実行せず、synthesize から再開する。

キャッシュと変更検知

flowchart TD Start["ステージ開始"] --> Hash["入力ファイルと設定からハッシュ計算"] Hash --> Same{"前回と同じ?<br/>出力も存在する?"} Same -->|Yes| Skip["ステージを省略"] Same -->|No| Run["処理を実行"] Run --> Save["出力と新しいハッシュを保存"] Skip --> Next["次のステージへ"] Save --> Next

ステージ単位のハッシュは job.json に保存する。合成だけはさらに細かく、チャンクIDごとのクエリハッシュを保存する。この二段構えにより、高価または時間のかかる処理を避けながら、手編集の変更を見逃さない。

TTS層の構造

Yomiagenは、すべての音声エンジンを最小公約数へ押し込めない。共通操作とエンジン固有の表現を3層に分け、VOICEVOXの細かな調整能力を失わずに将来のバックエンド追加余地を残している。

L1 Backend — 最小の共通契約
テキスト、声、話速、音量を受け取りWAVを返す。単純な音声合成バックエンドでも実装できる。
L2 QueryBackend — ネイティブ中間表現
テキストからAudioQueryのような編集可能表現を作り、その表現から合成する。未知のフィールドを失わないよう、ネイティブJSONをそのまま保持する。
L3 Refiner — 名前付き調整操作
accent、pause などをネイティブ表現へ適用する。機能対応はエンジンのcapability申告で判断する。

型とインターフェースは internal/tts/tts.go、VOICEVOX固有処理は internal/tts/voicevox/refine.go に置かれている。

現在の範囲と拡張点

現在使える範囲

  • 日本語を中心とするHTML、Markdown、プレーンテキストの取り込み
  • OpenAI利用またはローカルフォールバックによる台本化
  • VOICEVOXのAudioQueryを使った細かな読み・抑揚調整
  • WAV、M4A、MP3の出力とチャプター付与
  • ファイル編集を中心としたCLIレビュー運用

まだ実装していない範囲

  • AivisSpeech固有挙動への対応と実機検証
  • Google Cloud Text-to-Speechバックエンド
  • 文書内の言語に応じたチャンク単位のバックエンド切り替え
  • ブラウザ上で中間生成物を編集・試聴するWeb UI

新しい音声エンジンを追加するときも、エンジン固有表現を Query.Doc に保持し、対応機能を実行時に問い合わせる。共通インターフェースへ合わせるために、そのエンジン固有の表現力を削らない。
